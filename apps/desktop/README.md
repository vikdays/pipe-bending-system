# Настольное приложение руководителя

Windows: Wails 3.0.0 + Go, React + TypeScript. На macOS можно разрабатывать и собирать приложение; запуск и разрешения доступа на Windows необходимо отдельно проверить на Windows.

## Запуск

Из корня монорепозитория:

```bash
npm run desktop:native:start
```

Нужны Wails 3.0.0, Go и зависимости frontend (`npm ci` из `apps/desktop/frontend`). Если `wails3` не найден, добавьте каталог `$(go env GOPATH)/bin` в PATH.

При первом запуске создайте руководителя: логин от 3 до 64 символов (латиница, цифры, точка, дефис, подчёркивание, первая — буква), пароль от 15 до 128 символов. Используйте уникальную длинную парольную фразу. Встроенных паролей и демонстрационного входа больше нет. Логин приводится к нижнему регистру, пароль не обрезается и не нормализуется.

Нажмите на инициалы в правом верхнем углу для смены пароля и управления пользователями. Руководитель может создавать пользователей и блокировать другие учётные записи. Машинист может войти и сменить свой пароль, но рабочее место руководителя ему недоступно. Это локальные учётные записи ПК: они не передаются на Android вместе с заданием.

`npm run desktop:start` запускает только Vite на `http://127.0.0.1:9245`. Вход требует Wails, браузерный обход не предусмотрен. `desktop:native:build` собирает самостоятельное приложение в `apps/desktop/bin`; `desktop:build` — только frontend.

Для консоли настоящего Wails-приложения на macOS 13.3+ запустите `desktop:native:start`, в Safari включите «Настройки → Дополнения → Показывать функции для веб-разработчиков», затем выберите «Разработка → [этот Mac] → [приложение] → [страница окна]» и вкладку Console. В обычной dev-сборке WebView уже доступен для инспекции; `OpenDevTools()` на macOS требует отдельного тега `private_mac_apis`, поэтому добавлять вызов в `main.go` не требуется. Подробнее: [Wails](https://v3.wails.io/guides/build/private-macos-apis/), [WebKit](https://webkit.org/web-inspector/enabling-web-inspector/). Вывод Go (`log.Print`, `fmt.Print`) находится в терминале, где запущен Wails.

## Хранение и безопасность

Файл `application.sqlite3` создаётся в `PipeBendingControl` внутри `os.UserConfigDir()`:

- macOS: `~/Library/Application Support/PipeBendingControl/`;
- Windows: `%APPDATA%\PipeBendingControl\`.

База хранит пользователей, хеши паролей и токенов, сессии и счётчики неудачных попыток. Схема создаётся транзакционной миграцией; неизвестная более новая версия не открывается. Unix: каталог `0700`, файл `0600`. Windows: защищённый DACL для текущего пользователя ОС и SYSTEM. SQLite: журнал DELETE, внешние ключи, `secure_delete`, одна SQL-связь и параметризованные запросы.

Трубный журнал, реквизиты сертификатов и черновики заданий также сохраняются в этой SQLite. Сначала откройте «Трубный журнал → Добавить трубу», заполните инвентарный и заводской номера, диаметр, стенку и длину. Затем создайте задание, выбрав эту запись. Демонстрационные задания удалены; начальный журнал пуст. Рабочие БД и учётные данные не должны попадать в Git, пакеты обмена или на флешку.

В задании сохраняются `pipeId`, версия записи и полный снимок её характеристик. Изменение журнала не меняет ранее созданные задания. Общий сертификат можно связать с несколькими трубами, а заводские номера разных записей могут совпадать. Все основные графы изученного журнала доступны в форме, прочие сведения добавляются отдельными характеристиками. Подробнее: [схема и решения по хранению](../../docs/decisions/pipe-registry.md).

Подключены ручной ввод, импорт `.xlsx` с сохраняемым предпросмотром и оригиналы PDF сертификатов. Конфигурации технологии, сеансы, протоколы и файловый обмен ещё не подключены. Наличие черновика не означает резервирование трубы или проверенную пригодность к гибке.

## Импорт Excel и PDF

Запускайте именно Wails: из корня проекта `npm run desktop:native:start`. Системный диалог выбора файла и локальная БД доступны в настольном приложении.

1. Откройте **Трубный журнал → Импорт Excel → Выбрать .xlsx**.
2. Проверьте лист, строку заголовков, сопоставление столбцов и единицы. Для изученной книги предлагается лист «Трубный журнал», строка 2. Настройки можно изменить и перечитать оригинал; это сбросит исправления строк черновика.
3. Просмотрите состояния строк. **Новая** допускает добавление, **Уже в журнале** пропускается, **Ошибка** требует исправления, **Конфликт** не перезаписывает журнал, **Повтор в файле** не добавляется повторно. В «Исправить» доступна форма трубы и исходные ячейки. Неизвестные сведения оставляйте пустыми.
4. Выберите новые строки и нажмите **Добавить в журнал**. До этого журнал не меняется. Выбранные записи, сертификаты и связи сохраняются одной транзакцией. После перезапуска незавершённый импорт доступен в истории. Чтобы позже импортировать пропущенные строки завершённого импорта, снова выберите тот же файл: уже внесённые строки останутся пропущенными.
5. Откройте **Сертификаты и PDF**, выберите существующие реквизиты или создайте новый сертификат и нажмите **Прикрепить PDF**. Проверьте, что выбран правильный сертификат. PDF не распознаётся автоматически; характеристики не извлекаются и не меняются. Для связи сертификата с несколькими трубами выберите его в каждой карточке трубы.

Оригинал можно открыть в системном просмотрщике; PDF проверяется по SHA-256 перед открытием. «Снять привязку» скрывает связь с выбранным сертификатом и сохраняет остальные связи и оригинал. Повторное прикрепление восстанавливает связь. Учтите: SHA-256 проверяет неизменность содержимого, а не подлинность сертификата.

Лимит оригинала — 50 МБ. Только `.xlsx` без пароля и макросов: до 10 000 записей за импорт, до 50 000 строк / 128 столбцов на лист и 256 МБ после распаковки. Формулы не вычисляются; берутся сохранённые результаты, ошибки не заменяются нулями. Дополнительные столбцы сохраняются в происхождении строки вместе с исходным файлом. PDF должен быть пригоден для чтения без пароля.

Метаданные, черновики, история импорта и журнал привязок находятся в SQLite. Оригиналы — в `documents/` рядом с `application.sqlite3`, по хешу содержимого; исходные имена сохраняются в метаданных. Для резервной копии закройте приложение и сохраните **всю папку PipeBendingControl**, включая БД и `documents/`, в защищённое место вне Git. Замена только SQLite потеряет доступ к оригиналам. Это резервирование ПК, а не пакет обмена с Android.

- Пароли: Argon2id, случайная соль 16 байт, 64 MiB, 3 прохода, 1 поток, результат 32 байта. Одинаковые пароли имеют разные хеши. Параметры чтения ограничены фиксированной конфигурацией.
- Access/refresh: независимые непрозрачные случайные токены по 32 случайных байта, не JWT. В БД записывается SHA-256 токена; SHA-256 не применяется к паролям.
- Access действует 5 минут. Абсолютный срок сеанса — 8 часов; обновление его не продлевает.
- Refresh заменяется при каждом использовании внутри SQL-транзакции. Повтор старого refresh отзывает всё семейство, включая access-токены. Использованные хеши сохраняются для обнаружения повтора.
- Refresh находится только в памяти Go и не возвращается в Wails DTO. После полного закрытия приложения нужен пароль. Перезагрузка WebView в том же процессе может восстановить сеанс через Go.
- Access находится в замыкании TypeScript-клиента. Токены не записываются в localStorage/sessionStorage/URL. Одновременные обновления объединяются; ответ, опоздавший после выхода, не восстанавливает сеанс.
- Каждая защищённая Go-операция проверяет срок, отзыв, действительность пользователя и его роль по БД. Проверки React не являются границей безопасности. Прямой вызов административных bindings без прав также отклоняется.
- Выход, блокировка и смена пароля отзывают сессии. Разблокировка старые сессии не восстанавливает. Самоблокировка запрещена.
- Окно подсчёта ошибок — 15 минут; после 8 ошибок входа известная учётная запись блокируется на 5 минут. Общая блокировка после 30 ошибок также длится 5 минут. Лимиты сохраняются после перезапуска. Для неизвестного логина выполняется фиктивная Argon2-проверка; сообщение о неверных реквизитах одинаковое. Миграция 002 сокращает ранее записанные блокировки с 15 до 5 минут относительно момента их установки.
- Смена пароля требует текущий пароль, имеет отдельный лимит попыток и отзывает все сессии пользователя. Автоматического сброса или скрытой учётной записи нет.
- Пароли и исходные токены не логируются; хеши и внутренние SQL-ошибки не включаются в пользовательские DTO.

## Коды ошибок Wails

Все ошибки прикладного Go-сервиса имеют формат `{code, message}`. Сериализатор `ServiceOptions.MarshalError` помещает его в `RuntimeError.cause`. Frontend-клиент создаёт `AppError`, доступный в `catch`. Числового `status` и собственного REST API здесь нет.

| Код | Ситуация |
| --- | --- |
| `VALIDATION_ERROR` | Некорректные данные при создании пользователя/смене пароля, недопустимая роль, изменение собственной блокировки |
| `INVALID_CREDENTIALS` | Неверные реквизиты или текущий пароль; блокировка известного логина маскируется этим же ответом |
| `UNAUTHENTICATED` | Отсутствующая, истёкшая или отозванная сессия |
| `FORBIDDEN` | Нет прав на административное действие |
| `NOT_FOUND` | Изменяемая учётная запись не найдена (после проверки прав) |
| `CONFLICT` | Логин занят либо первоначальная настройка уже выполнена |
| `RATE_LIMITED` | Общий лимит входа или лимит смены пароля |
| `INTERNAL_ERROR` | Ошибка БД либо неизвестная внутренняя ошибка |

`internal/apperror` определяет коды и безопасную сериализацию. `authservice.go` удаляет внутренний текст обёрток и заменяет неизвестные ошибки безопасным `INTERNAL_ERROR` до передачи в Wails. Frontend `appError.ts` проверяет `cause`, создаёт `AppError` с `code/message` и не отображает необработанные транспортные сообщения. Нет проверок по тексту перевода.

`UNAUTHENTICATED` требует повторного входа, `INVALID_CREDENTIALS` при смене пароля оставляет действующую сессию. `FORBIDDEN` и временный `INTERNAL_ERROR` обычной защищённой операции также не означают выход. При ошибке refresh Go удаляет refresh из памяти, поэтому клиент завершает локальную сессию, сохраняя фактический код причины. Сбой фоновой проверки БД отображается предупреждением; после успешной проверки оно исчезает.

REST API обычно адресует ресурсы через URL и HTTP-методы, например `POST /auth/login`, и использует HTTP-статус ответа. Наш desktop вызывает зарегистрированный метод `DesktopAuthService.Login(...)` через сгенерированный мост Wails; писать HTTP-маршрут для этого не требуется. RPC означает вызов процедуры через границу выполнения: в нашем случае из JavaScript WebView в Go на том же ПК, без требования Интернета. Внутренний транспорт Wails может использовать HTTP, но его технические статусы не заменяют прикладной `code`. Если позже появится отдельный REST API, сопоставление прикладных кодов с HTTP-статусами добавляется на его границе.

В `examples/contracts/app-errors.json` находятся вымышленные примеры общего контракта. Их проверяют и Go-, и TypeScript-тесты. При добавлении нового кода обновите обе стороны и примеры.

## Границы защиты

SQLite здесь **не зашифрована**. Хеширование, ACL и `secure_delete` не заменяют шифрование диска и не гарантируют стирание данных на SSD/в резервных копиях. Для защиты при краже накопителя нужны BitLocker/FileVault либо отдельное шифрованное хранилище с ключом в системном защищённом хранилище. Ключ нельзя хранить рядом с базой.

Доверяем профилю ОС и его владельцу, в том числе при первоначальной настройке. Владелец профиля, администратор ОС или вредоносная программа с доступом к процессу могут читать память/изменять приложение и базу. Локальная аутентификация от этого не защищает. HTTP-сервер авторизации не добавлен; не публикуйте dev-сервер во внешнюю сеть.

Это прототип, не результат независимого аудита. До развёртывания нужны проверка Windows ACL на устройстве, политика восстановления доступа, защита диска и резервных копий, проверка модели угроз. Android-аутентификация этим изменением не реализуется.

## Проверки

Из корня:

```bash
npm run desktop:go:test
npm run desktop:typecheck
npm run desktop:lint
npm run desktop:test
npm run desktop:build
```

Из `apps/desktop`: `go test -race ./internal/... .` и `go vet ./internal/... .`.

Go-тесты работают только с временными базами и вымышленными паролями. Проверяют истечение, отзыв, повтор refresh, права, блокировку, смену пароля, лимиты, миграцию и перезапуск. Frontend-тесты проверяют обновление и гонки с выходом. Генерируемые `frontend/bindings` не редактируются: Wails создаёт их при сборке.

## Основные файлы

- `main.go` — открытие БД, регистрация сервиса и окно.
- `authservice.go` — граница Wails: refresh остаётся в Go, frontend получает access и безопасные поля пользователя.
- `registryservice.go` — защищённые методы Wails для труб, сертификатов и заданий; перед каждой операцией проверяется действующая сессия руководителя.
- `internal/registry` — валидация, транзакционная запись журнала, связи сертификатов, версии и снимки труб в заданиях.
- `internal/auth` — пароли, сессии, токены, роли и лимиты, без зависимости от Wails.
- `internal/storage` — файл БД, разрешения доступа и миграции.
- `frontend/src/features/auth` — клиент bindings, первый запуск, вход, управление пользователями и смена пароля.
- `frontend/src/features/dashboard` — композиция главного экрана и состояние представления.
- `frontend/src/features/pipes` — журнал, карточка трубы, дополнительные характеристики и клиент Go-сервиса.
- `frontend/src/features/tasks` — сохранённые задания, таблица, фильтры и карточки.
- `frontend/src/components/layout` — оболочка и навигация.

Основания решений: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [RFC 9700, раздел 4.14](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14). Используется принцип ротации; реализация полного OAuth-сервера не заявляется.
