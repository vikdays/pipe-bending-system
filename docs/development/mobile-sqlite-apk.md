# Мобильная SQLite и проверка самостоятельного APK

Реализован первый мобильный этап: локальная БД, список заданий, карточка и импорт JSON с предпросмотром. Самостоятельный release APK собран в EAS 06.11.2026. Целевая проверка — Huawei Pura 70 Pro с EMUI 14.2.0. Физическая установка и работа в авиарежиме ещё требуют проверки на телефоне.

## Что означает «подключить SQLite на телефон»

SQLite встроена в приложение библиотекой `expo-sqlite`. Отдельно ставить SQLite, открывать порт, вводить адрес ПК или переносить его рабочую базу не нужно. При первом запуске приложение само создаёт файл `pipe-bending-mobile.sqlite3` в приватном каталоге приложения и применяет миграцию версии 1. При следующих запусках открывает тот же файл. Интернет для этого не используется.

Три таблицы:

- `mobile_tasks` — UUID, ревизия, номер и позиция задания, полный JSON со снимками трубы, конфигурации и станка, SHA-256, первый пакет и время импорта.
- `imported_packages` — успешно принятые пакеты: контрольная сумма нормализованного JSON, формат, версия, имя файла, количество заданий и время.
- `imported_package_tasks` — состав каждого пакета, включая уже имевшиеся задания.

Файл БД принадлежит этому устройству. Оригинал импортированного JSON остаётся у пользователя; для работы достаточно сохранённых данных SQLite. Приватный каталог и отключённое резервное копирование Android не означают шифрование SQLite: SQLCipher и мобильное управление доступом в этот этап не входят.

## Где находится код

- `apps/mobile/src/storage/database.ts` — открытие единственного подключения SQLite и SHA-256 через Expo Crypto.
- `apps/mobile/src/storage/migrations/001-tasks.ts` — создание таблиц и защита содержимого задания от изменения.
- `apps/mobile/src/storage/taskRepository.ts` — SQL, миграция, очередь операций и транзакционный импорт. Параметры передаются через SQL placeholders. Подключение не выдаётся компонентам.
- `apps/mobile/src/storage/TaskStorageProvider.tsx` — загрузка БД до показа экранов, ошибки открытия и повторная попытка.
- `apps/mobile/src/features/tasks/taskPackage.ts` — проверка по общему `packages/contracts/tasks-v1.schema.json`, версии, UUID, очереди и снимков. Максимум 1000 заданий и 8 МБ на пакет.
- `apps/mobile/src/features/tasks/pickTaskPackage.ts` — системный выбор файла, чтение копии в кэше и очистка только этой копии.
- `apps/mobile/src/features/tasks/useTaskList.ts` — состояние списка, предпросмотра и подтверждения импорта.
- `TaskListScreen.tsx`, `TaskDetailsScreen.tsx`, `taskStyles.ts` в той же папке — два экрана и их оформление.
- `apps/mobile/src/app` — только маршруты Expo Router и оболочка.
- `apps/mobile/eas.json` — профиль `preview`, создающий release APK без development client.
- Корневой `.easignore` — разрешённый состав облачной сборки: мобильный проект и JSON-контракт. Desktop, документы, БД, ключи и локальные данные исключены. При появлении новых зависимостей вне mobile этот список нужно обновить.

## 1. Проверить код на Mac

Открой терминал в папке мобильного приложения:

```bash
cd /Users/vikdays/Documents/devtools/projects/pipe-bending-mobile/apps/mobile
npm ci
npm run typecheck
npm test
```

Зависимости в текущей рабочей папке уже установлены. `npm ci` нужен на другом компьютере или после получения обновлений; он устанавливает версии из lock-файла. Для тестов нужен Node.js 24: они используют настоящую SQLite через `node:sqlite` и временный файл, а не имитацию SQL.

Для быстрой проверки интерфейса через Expo Go:

```bash
npx expo start --go
```

Это проверка разработки. Она не подтверждает автономность APK: Expo Go загружает код из Metro. После изменения маршрутов запуск Expo обновляет игнорируемые типы в `.expo/types`; вручную их редактировать не нужно.

## 2. Собрать самостоятельный APK

На этом Mac обнаружена Java 21, но не обнаружены Android SDK и `adb`. Проект уже привязан к `@vikdays/pipe-bending-mobile`; повторно создавать его не нужно. Для первого APK можно использовать облачную сборку Expo (EAS); Android Studio для неё не нужен. Интернет нужен Mac для сборки и телефону для скачивания APK, но не для дальнейшей работы приложения.

Все следующие команды выполняй в `apps/mobile`:

```bash
cd /Users/vikdays/Documents/devtools/projects/pipe-bending-mobile/apps/mobile
npx --yes eas-cli@27.5.0 login
npx --yes eas-cli@27.5.0 whoami
npx --yes eas-cli@27.5.0 init
npm run apk:build
```

1. В `login` войди в свою учётную запись Expo; если её нет, сначала создай на https://expo.dev/signup . Пароль вводится в терминале, не в чате.
2. `whoami` должен вывести твой логин.
3. `init` привязывает приложение к EAS-проекту. Для первого запуска выбери создание проекта `pipe-bending-mobile`; если он уже существует, выбери свой существующий проект. Команда сохранит реальный `extra.eas.projectId` в `app.json`. Выдумывать UUID проекта нельзя.
4. `apk:build` запускает профиль `preview`: `developmentClient: false`, `distribution: internal`, `android.buildType: apk`. При первом запросе подписи разреши EAS создать Android keystore. Используй ту же подпись для последующих обновлений, чтобы не приходилось удалять приложение и терять его БД.
5. Дождись успешного окончания сборки. По выданной ссылке нужен файл **`.apk`**, а не `.aab`. Если облачный сервис предлагает платную сборку, сначала проверь доступный тариф; платный запуск не требуется автоматически.

Исходники этого приложения передаются EAS для компиляции. Производственные файлы в сборку не входят. Google Play, Google-аккаунт и Google Play Services не нужны для текущих функций SQLite и выбора файлов.

## 3. Установить на Huawei

1. Открой ссылку завершённой сборки на телефоне и скачай APK. Для первой проверки не нужна флешка.
2. Открой APK в браузере или приложении «Файлы» и выбери установку.
3. Если EMUI запросит разрешение, разреши **этому браузеру или «Файлам»** установку приложений из внешнего источника. Обычно настройка находится в разделе безопасности; точное название зависит от локализации EMUI. Отключать всю защиту телефона не нужно.
4. Найди на рабочем столе **«Контроль гибки»** и запусти именно его. Android package: `ru.kononets.pipebending.operator`.
5. На первом запуске ожидается пустой список и кнопка «Импортировать задания». Если открывается Expo Go или экран выбора Metro-сервера, установлен не самостоятельный `preview` APK.

Установка поверх предыдущего APK с тем же package и подписью должна сохранять приватную БД. Удаление приложения или действие «Очистить данные» удаляет её. Не делай этого при проверке сохранности.

## 4. Перенести JSON и импортировать

1. В настольном приложении создай и подготовь задания, затем нажми «Выгрузить задания» и сохрани один JSON.
2. Сохрани JSON в память телефона, например в «Загрузки». Для первой функциональной проверки можно скачать собственный файл на телефон; это отдельный подготовительный шаг, приложение не обращается к облаку. В дальнейшем выбери этот же файл с флешки через USB-C/OTG. Настоящий USB-носитель проверяется отдельно.
3. Для проверки на вымышленных данных есть `examples/tasks/tasks-v1.json` с тремя заданиями. Он не загружается в БД автоматически. Используй его вместо производственного пакета на пустой тестовой установке: позиции очереди 1–3 не должны смешиваться с другой очередью.
4. На телефоне нажми «Импортировать задания», выбери `.json` в системном файловом диалоге.
5. Проверь имя файла, список и порядок заданий. Нажми «Сохранить задания (N)». До подтверждения SQLite не изменяется.
6. Открой карточку, проверь трубу, станок, цель и параметры из снимков. Кнопка «Следующее задание» открывает следующую карточку, но не начинает сеанс и не отмечает выполнение.

Повтор того же пакета, включая переименованный/переформатированный файл, не создаёт дубликаты. Одинаковый UUID/ревизия с другим содержимым отклоняет весь пакет. Новая ревизия для существующего UUID пока тоже отклоняется. Уже имеющиеся задания в частично пересекающемся пакете пропускаются, новые добавляются атомарно. Позиции очереди уникальны для одного исходного ПК; смешивать независимые очереди с нескольких ПК формат v1 пока не позволяет.

## 5. Подтвердить автономную работу

1. После импорта запомни число заданий и данные одной карточки.
2. На Mac останови Metro клавишами `Ctrl+C` и закрой приложение руководителя.
3. На телефоне включи авиарежим и отдельно убедись, что Wi-Fi выключен.
4. Полностью останови «Контроль гибки» через настройки приложения. Не нажимай «Очистить данные».
5. Открой приложение с рабочего стола. Список и карточка должны содержать те же данные.
6. Перезагрузи сам телефон и повтори проверку без Интернета и компьютера.
7. Повтори импорт сохранённого JSON: счётчик заданий не должен вырасти. Отмена выбора файла или предпросмотра тоже не должна менять данные.

Именно успешная проверка на устройстве закрывает пункт про самостоятельный APK. TypeScript, SQL-тесты и сборка JS-бандла сами по себе её не заменяют.

## Проверки реализации

Проверены TypeScript, Android/Hermes-бандл, совместимость зависимостей Expo SDK 58, Expo Doctor (20/20) и 9 интеграционных проверок на настоящей SQLite: повторное открытие файла БД, порядок, снимки, повтор пакета, параллельные подтверждения, частичное пересечение пакетов, откат конфликтов и ошибок записи, восстановление после ошибки, внешние ключи и SQL-параметры. Это проверки кода и хранилища на Mac; фактический запуск APK на Huawei отмечается отдельно после ручной проверки.

Корневой `npm run lint` пока не проходит: мобильный ESLint не настроен; автоматическая установка не выполнялась.

В облачном журнале этой сборки Expo Doctor оставил предупреждение про игнорирование `.expo`. Локальное правило добавлено в `apps/mobile/.gitignore`, после чего повторная проверка на Mac прошла 20/20. Сам каталог `.expo` не передавался в EAS: он исключён из архива отдельным правилом. Изменение `.gitignore` не меняет исполняемый код APK.
