# Первая загрузка монорепозитория на GitHub

Инструкция для существующего проекта на Mac. В корне уже есть `.git` и первый
коммит. Повторно выполнять `git init`, клонировать пустой репозиторий поверх
проекта или создавать отдельные репозитории внутри `apps` не требуется.

Рекомендуемое имя на GitHub — `pipe-bending-system`. Локальная папка может
остаться `pipe-bending-mobile`. Это не мешает связать её с репозиторием другого имени.

## 1. Создать пустой приватный репозиторий в браузере

Откройте [создание репозитория GitHub](https://github.com/new) и войдите в аккаунт.

1. В `Owner` выберите свой аккаунт.
2. В `Repository name` укажите `pipe-bending-system`.
3. При желании добавьте описание: `Автономная система цифрового контроля гибки труб. ВКР`.
4. Выберите **Private**.
5. Не добавляйте README, `.gitignore` или лицензию через GitHub: эти файлы уже есть локально.
6. Нажмите **Create repository**.

Ожидаемый результат — пустой репозиторий со страницей `Quick setup` и адресом
вида `https://github.com/YOUR_LOGIN/pipe-bending-system.git`.

`"private": true` в `package.json` относится к публикации npm-пакета.
Приватность GitHub задаётся отдельно выбором **Private** на сайте.

## 2. Открыть терминал в корне проекта

Дальнейшие команды выполняйте здесь:

```bash
cd /Users/vikdays/Documents/devtools/projects/pipe-bending-mobile
pwd
git status
```

`pwd` должен показать эту папку. `git status` покажет перенесённые файлы и новые
директории. До первого коммита Git может показывать перенос как удаление старого
пути и появление нового; содержимое приложения находится в `apps/mobile`.

## 3. Проверить имя и email автора коммитов

```bash
git config --get user.name
git config --get user.email
```

Если значения уже верны, ничего менять не нужно. Если их нет, задайте для этого
репозитория, заменив `YOUR_EMAIL` своим email GitHub или адресом noreply
из [настроек email](https://github.com/settings/emails):

```bash
git config user.name "Кононец Виктория Вячеславовна"
git config user.email "YOUR_EMAIL"
```

Здесь нет `--global`: настройка относится только к этому проекту.
Она определяет авторство коммита, а не выполняет вход в аккаунт GitHub.

## 4. Проверить файлы и подготовить коммит

```bash
git status --short
git add -A
git diff --cached --stat
git diff --cached --name-only
```

`git add -A` подготавливает изменения, включая перенос и удаление старых путей,
но пока ничего не отправляет в Интернет. Следующие команды показывают состав коммита.

В списке должны быть код, ресурсы приложения, документы разработки,
`apps/mobile/package-lock.json` и файлы `.gitkeep`.
`node_modules`, `.expo`, архивный `example`, локальные базы, `.env`, APK и реальные
материалы из `local-data` не должны попадать в коммит.

Если случайно подготовили ненужный файл, уберите только его из коммита:

```bash
git restore --staged путь/к/файлу
```

Файл останется на диске. Замените пример пути нужным именем.
Реальные производственные документы храните в `local-data`, а не в `examples`.

## 5. Сохранить структуру локальным коммитом

```bash
git commit -m "Organize monorepo structure"
git status
```

Коммит сохраняет снимок подготовленных файлов в локальной истории.
Ожидаемый результат `git status` — отсутствие неподготовленных изменений,
если после подготовки вы ничего не редактировали.

## 6. Назвать основную ветку main

```bash
git branch --show-current
```

На момент подготовки структуры ветка называлась `master`. Если вывод по-прежнему
`master`, переименуйте её:

```bash
git branch -m main
```

Если уже выводится `main`, этот шаг пропускается. Переименование не создаёт новый
проект и не удаляет коммиты. Если вы уже работаете в другой ветке, сначала
разберитесь с её назначением, а не переименовывайте её автоматически.

## 7. Подключить адрес GitHub

Скопируйте **HTTPS**-адрес из созданного репозитория. Ниже замените `YOUR_LOGIN`
своим логином и при необходимости имя репозитория:

```bash
git remote -v
git remote add origin https://github.com/YOUR_LOGIN/pipe-bending-system.git
git remote -v
```

`origin` — короткое имя удалённого репозитория. После добавления должны появиться
две строки с вашим адресом: для `fetch` и `push`.

Если `origin` уже есть и адрес правильный, повторный `remote add` пропускается.
Если адрес отличается, сначала проверьте, какой репозиторий вы хотите подключить.

## 8. Войти в GitHub при необходимости

Если вход для Git уже настроен на этом Mac, дополнительных действий может не быть.
Вход на сайт в браузере сам по себе не всегда авторизует терминал.

При использовании HTTPS GitHub не принимает обычный пароль аккаунта для Git.
Используйте настроенный менеджер учётных данных или personal access token.
Если Git спрашивает `Username`, укажите логин; в поле `Password` вводится токен.
Ввод токена обычно не отображается в терминале — это нормально.

Если токена ещё нет, создайте его по [официальной инструкции GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens):
для fine-grained токена выберите нужный аккаунт, доступ к этому репозиторию и
разрешение `Contents: Read and write`. Укажите срок действия.
Токен не вставляйте в команду remote, исходный код, README или чат.

Альтернатива — войти через браузер в GitHub Desktop и добавить существующий
локальный репозиторий. Для этого не нужно переносить или клонировать проект заново.

## 9. Отправить коммиты

Из того же корня:

```bash
git push -u origin main
```

Команда отправляет историю в GitHub и связывает локальную `main` с удалённой.
Успех обычно сопровождается строками о новой ветке и её отслеживании.

Если появляется ошибка доступа, проверьте логин, адрес и авторизацию.
Если появляется `rejected`, не используйте `--force`: возможно, в удалённом
репозитории уже создан README или другой коммит. Такую ситуацию нужно разобрать
по точному тексту ошибки с сохранением обеих историй.

## 10. Проверить результат

Обновите страницу GitHub. Должны быть видны `apps`, `packages`, `docs`, `examples`,
`tests`, `scripts`, README и пометка **Private**. Откройте `apps/mobile/src/app/index.tsx`
и убедитесь, что это ваш экран. Проверьте, что рабочих БД и `node_modules` нет.

В терминале:

```bash
git status
git log -2 --oneline
```

Это показывает локальное состояние и последние коммиты. Проверка страницы GitHub
подтверждает, что файлы действительно дошли до удалённого репозитория.

## Как отправлять следующие изменения

После небольшого законченного изменения из корня:

```bash
npm run typecheck
npm run lint
git status
git add -A
git diff --cached --stat
git commit -m "Describe the completed change"
git push
```

Заменяйте сообщение коммита понятным описанием своей работы.
Линтер заработает после первоначальной установки его зависимостей; сейчас эта
настройка ещё не завершена. Сборку/запуск приложения проверяйте по мере изменений.

При желании следующую самостоятельную задачу можно делать в отдельной ветке:

```bash
git switch -c codex/task-exchange
```

Это пример ветки для формата обмена. Отправлять её впервые нужно через
`git push -u origin codex/task-exchange`; после проверки изменения можно объединить
с основной веткой через pull request.

Инструкция сверена с [GitHub Docs: добавление локального кода](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github)
и [GitHub Docs: авторизация](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/about-authentication-to-github).
